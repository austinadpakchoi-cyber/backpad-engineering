# BackPad 技术方案

随缘团队 · 王宝晨、李希文

横屏远程操作电脑时，手指在手机正面拖选文字，容易挡住选区端点。BackPad 将触控面移到手机背后，让食指移动光标、中指配合滚动。以复制一句话为例，使用者可以看着屏幕上的选区，在背面拖动并微调选区末端。团队已用华为 P40 Pro、HarmonyOS 4.2 和 UU 远程联调 Windows。磁吸卡包外形仍在打样。

它沿用常见触控板的操作。单击用于选择，双击用于打开，按住拖动可以选择文字或移动对象，双指滑动可以滚动页面。团队正在开发 24 键单手输入键盘，目标是减少横屏操作时从定位切换到输入的次数。

## 一次滑动怎样到达电脑

| 部件 | 工作 |
| --- | --- |
| IQS9151 触控子板 | 电极阵列检测指腹位置、接触面积和电容信号强度。两块板由 FPC 排线连接。 |
| nRF52840 主控板 | 在 RDY 有效时通过 400 kHz I²C 总线读取触点。根据近期轨迹识别移动、轻点、双击、拖动和滚动。 |
| 手机与远程电脑 | 主控通过蓝牙 HID 发送按钮、相对位移和滚轮共 4 字节。手机接收鼠标输入，UU 将其转发至 Windows。 |

## 为什么用了 NVIDIA GPU

使用者反馈，食指一直贴在背面时滑动较顺，快速抬手再落下时却可能“划了没动”。换一个手指角度重试会同时改变接触面积、坐标和力度，很难区分原因。团队保留了一段 1,600 帧的真实采样，单独改变其中短划起始处的**电容信号强度**，观察固件决策如何变化。

在 **GeForce RTX 4080 SUPER** 上，PyTorch 通过 CUDA 对同一输入批量生成 5 种衰减幅度和 6 种持续时间的组合，另留一组零扰动对照。各组保留原来的坐标、面积和帧间隔。CPU 用独立的整数公式逐值核对全部 49,600 个强度值，随后用产品的 C 代码逐组回放，读取输出报告。GPU 用在开发工作站上，用户手上的 BackPad 仍由 nRF52840 运行。

| 同一原始短划的不同输入 | 移动报告数 | 按钮非零报告数 | 窗口起点至首条移动 |
| --- | ---: | ---: | ---: |
| 真实原始输入 | 16 | 0 | 101 ms |
| 强度降低 30%，持续 24 ms（4 帧） | 0 | 1 | 窗口内无移动 |
| 强度降低 30%，持续 96 ms（16 帧） | 10 | 0 | 119 ms |

30 个衍生条件中，23 组在目标窗口内没有移动报告，其中 20 组还出现按钮非零报告。各组结束时按钮均已释放。上述数量反映单条轨迹对人工扰动的敏感性；首条报告时间取自离线回放，手机显示延迟和实际用户漏划率需要实测。电容强度变化也不能直接换算成指腹施力。

## 1 mm PLA 盖板的固件调校

换成 1 mm PLA 盖板后，团队在手机横屏场景采集指尖短划、指腹短划和原地轻点。采集按 30 秒一组，同时保留板端触点和 UU 收到的事件。板端轨迹用两版 C 固件回放，以区分触点处理与远程转发各自的影响。

| 问题 | 当前处理 |
| --- | --- |
| 弱触重新落指时，滑动证据出现得比触点接纳更早 | 保留落指前后连贯的单指轨迹，供接纳后的运动判定使用。 |
| 面积指数为 3 的短划低于常规接纳门槛 | 单独核对信号密度和连续同向轨迹。只有运动证据达到条件才允许这类单指起步，该路径只输出位移。 |
| 单指已接纳，信号下降触发抬手保护，继续划动也没有输出 | 在早期冻结期间保留原始轨迹，从仍满足强度与同向移动条件的窗口恢复移动，限制首条报告的追赶位移。 |

当前常规接纳与保持面积门槛分别为 **4 / 3**，面积是触控芯片报告的指数。背面横屏方案在板端启动时使用 **0°、左右翻转**的映射。两段典型误点回放各由 **0 移动、1 次按下**变为 **15 条移动报告、0 次按下**。两段短划的 16 组输入扰动通过，原地轻点回放保持零移动，双击、拖动、滚轮与抬手用例通过回归。新版固件已构建、烧录和读回核验。另有冻结片段待优化，新版固件在同一盖板和远程链路上的实机体验待复测。见[验证摘要](../validation/pla-continuity-20261118.json)和[工程记录](ENGINEERING.md)。

历史 R2 的轨迹窗口整理，将逐点移除改为一次搬移有效点。同一份 1,600 帧输入的内存搬移从 311 次降至 302 次，419 条 HID 报告的内容和时间戳相同。[构建与回放记录](../validation/intent-window-20261118.json)

## 端侧分类研究

团队曾用 IQS550 的 15 × 10 × 3 电容矩阵数据训练触摸状态与手指数量分类模型，完成 int8 导出、nRF52840 目标编译和 Cortex-M4 仿真核对。当前 IQS9151 实机的手势判定由上述 C 固件执行。后续计划验证 IQS9151 输入适配和板上推理，再评估触点分类是否能帮助区分微动与抬手。

## 复现与资料

在仓库根目录运行下列命令，复现公开的历史 R2 固定样本和压力扰动实验。第一条需要 Python 3.10+ 和 C11 编译器，第三条另需支持 CUDA 的 PyTorch 与 NVIDIA GPU。同一脚本支持 `--device cpu`，可用 CPU 单独复核。最新 1 mm PLA 验证另有结果摘要。

```sh
python tools/reproduce.py --out .build/replay
python -B tools/profile_intent_window.py
python -B tools/pressure_sweep.py --device cuda --out pressure-sweep.json
```
