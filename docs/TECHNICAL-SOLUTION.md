# BackPad 技术方案

随缘团队 · 王宝晨、李希文

横屏远程操作电脑时，文件名和表格单元格在手机上很小。BackPad 将触控面移到手机背后，让食指移动光标、中指配合滚动，使用者可以一直看到要点选的位置。团队已用华为 P40 Pro、HarmonyOS 4.2 和 UU 远程联调 Windows。磁吸卡包外形仍在打样。

## 一次滑动怎样到达电脑

| 部件 | 工作 |
| --- | --- |
| IQS9151 触控子板 | 电极阵列检测指腹位置、接触面积和电容信号强度。两块板由 FPC 排线连接。 |
| nRF52840 主控板 | 在 RDY 有效时通过 400 kHz I²C 总线读取触点。根据近期轨迹识别移动、轻点、双击、拖动和滚动。 |
| 手机与远程电脑 | 主控通过蓝牙 HID 发送按钮、相对位移和滚轮共 4 字节。手机接收鼠标输入，UU 将其转发至 Windows。 |

## 为什么用了 NVIDIA GPU

使用者反馈，食指一直贴在背面时滑动较顺，快速抬手再落下时却可能“划了没动”。换一个手指角度重试会同时改变接触面积、坐标和力度，很难区分原因。团队保留了一段 1,600 帧的真实采样，单独改变其中短划起始处的**电容信号强度**，观察固件决策如何变化。

在 **GeForce RTX 4080 SUPER** 上，PyTorch 通过 CUDA 对同一输入批量生成 5 种衰减幅度和 6 种持续时间的组合，另留一组零扰动对照。各组保留原来的坐标、面积和帧间隔。CPU 用独立的整数公式逐值核对全部 49,600 个强度值，随后用产品的 C 代码逐组回放，读取输出报告。GPU 用在开发工作站上，用户手上的 BackPad 仍由 nRF52840 运行。

| 同一原始短划的不同输入 | 移动报告数 | 按钮非零报告数 | 窗口起点至首条移动 |
| --- | ---: | ---: | ---: |
| 真实原始输入 | 16 | 0 | 101 ms |
| 强度降低 30%，持续 24 ms（4 帧） | 0 | 1 | 窗口内无移动 |
| 强度降低 30%，持续 96 ms（16 帧） | 10 | 0 | 119 ms |

30 个衍生条件中，23 组在目标窗口内没有移动报告，其中 20 组还出现按钮非零报告。各组结束时按钮均已释放。上述数量反映单条轨迹对人工扰动的敏感性；首条报告时间取自离线回放，手机显示延迟和实际用户漏划率需要实测。电容强度变化也不能直接换算成指腹施力。

## 固件改动与复测

主控会保存近期触点来判断滑动方向。当时间窗口缩短，原实现每移除一个过期点就搬移一次数组。本次候选先找出所有过期点，再将有效点整体搬移一次。回放同一份 1,600 帧输入，在这个清理步骤中，内存搬移从 311 次降至 302 次，少搬 4,928 字节（2.68%）。419 条 HID 报告的内容和时间戳与历史 R2 逐条相同，18 组停止与抬手用例的结果也相同。设备端实际延迟仍需测量。候选固件已通过 nRF52840 目标构建，Flash 占用 408,644 字节（比历史参考增加 32 字节），RAM 占用 228,224 字节（持平）。本轮未烧录。[构建与回放记录](../validation/intent-window-20261118.json)

回归工具现在还检查停止、抬手期间有无错误左键按下，即使最后已经松开也能检出。

下一轮实机将分别采集 **30 秒快速续滑**和 **30 秒小目标微调**。用同一台手机、盖板和握姿，同步记录板端强度、首条移动、按键事件和远程电脑收到的输入，另用轻点、双击、拖动与双指滚动检查副作用。优先复查最初几帧信号变弱的样本，再决定是否调整落指识别门槛。

## 复现与资料

在仓库根目录运行下列命令。第一条需要 Python 3.10+ 和 C11 编译器，第三条另需支持 CUDA 的 PyTorch 与 NVIDIA GPU。同一脚本支持 `--device cpu`，可用 CPU 单独复核。

```sh
python tools/reproduce.py --out .build/replay
python -B tools/profile_intent_window.py
python -B tools/pressure_sweep.py --device cuda --out pressure-sweep.json
```
