# 三个工程案例：需求、反例与验证

场景是手机握持与远程操作：快划要到远目标，慢速要微调，停下不能漂移；点击/拖动/双指手势不能为了一个移动缺陷被一并破坏。“压力”指strength/area信号代理，不是压力传感器标定值。

## 1. 压力下降：为什么继续滑动却不再输出

**现象。** 真实失败片段中v0.20.15目标区间0次移动，却出现1次按下报告；维护者此前已实测反馈离线改进没有带来可感知改善，并指出8秒混合测试不足以分清快划与微调。

**约束。** 保留已有触点准入、点击、拖动和滚轮时序；避免为提高响应直接去掉抬手保护；输出冻结期间也不能丢失能支持连续滑动的轨迹。

**根因依据。** [bp_touch_convert](../firmware/app/src/bp_touch_policy.c#L394)的低压力/近期峰值判断会清掉当前active运动证据。v15的实际历史条件由[小补丁](../samples/variants/v15-bp_touch_policy.c.patch)还原，而非人工编造一个更差的“before”。[intent_observe](../firmware/app/src/bp_touch_policy.c#L114)是观察独立意图的入口。

**修复机制。** 输出可信度与意图积累分开：在有效单指、非弱触摸和双指保护约束下，即便暂不输出位置，轨迹仍进入意图拟合。恢复时需要当前active证据，不能仅凭压力下降一律清空。保持正在进行的滑动，新的冻结恢复则要求严格当前拟合。

**替代/失败。** 直接移除压力门限会把停住后的质心漂移带回输出；直接复用旧意图也可能恢复早已结束的运动。因此压力连续性R1只作为中间尝试，须结合案例2收紧。

**验证。** 本轮编译原C算法，同一真实输入v15为0motion/1pressed，R1和R2为16motion/0pressed。整个公开回放不是端到端手机实验；原始与公开入口/脱敏数据输出逐事件比对一致。输入与结果分别见[metadata](../samples/pressure-drop/metadata.json)、[执行记录](../validation/local-20261116.json)。

**状态。** 机制、固定样本对照已复现；不能据一个样本宣称整体准确率提高或所有手感问题已解决。

## 2. R1反例：曾经移动过，不等于现在仍在移动

**现象。** R1解决上一个片段后，在“移动→停住→压力下降/质心尾移”反例里出现新增尾迹。只看成功片段会漏掉这个副作用。

**约束。** 保留连续滑动，不允许先前的confirmed状态无限延长恢复资格；恢复须符合当前证据，而不是从历史缓存借一次许可。

**根因依据。** R1条件为`active && (was_confirmed || pressure_safe)`。它只看“这次接触曾经确认”，没有区分进入当前观察前是否仍active。[R1实际差异](../samples/variants/r1-bp_touch_policy.c.patch)

**修复机制。** R2保存`was_active`，改为`active && ((was_confirmed && was_active) || pressure_safe)`。严格的新拟合要求当前窗口≥40ms、解释方差≥95%、strength范围不超过20%；不满足有效滑动且相对30ms近期峰值跌至90%以下时，不让尾迹重新获得active。见[bp_touch_policy.c](../firmware/app/src/bp_touch_policy.c#L680)。这些阈值是当前版本选择，不是普适物理定律。

**替代/失败。** “曾confirmed即放行”保留为可运行R1反例；完全恢复v15则丢失案例1的真实滑动。R2用当前连续性与严格新拟合区分二者。

**验证。** 复用[18项合成用例](../tools/release_tail.c)：帧间隔、尾移和尾移时长组合，比较相同条件v15。R1有6项新增尾移>1 HID count，R2为0项。合成输入明确标记，不占用“17组真实回放”的名额。

**状态。** 固定用例上的修复与反例均可重现；0项回归不等于所有真实抬手绝对0漂移。

## 3. 恢复位置与验证分层：不一次释放冻结位移

**现象。** 冻结输出后若直接把新的原始坐标当连续输出，积累的距离可能一次释放，表现为跳动。另一方面，离线指标改善也可能与持机真实手感不一致。

**约束。** 既要允许当前有效移动恢复，又不能把悬停/握持变化期间积累的坐标当作用户有意移动；不能重置到任意原点破坏连续性。

**根因依据。** 传感/意图观察位置与已输出位置不相同。[恢复分支](../firmware/app/src/bp_touch_policy.c#L718)保留最后发出位置作为恢复锚点；后续核心的movement与tap状态仍按原链路处理。代码体现具体机制；本轮没有孤立该机制的消融试验，不能单独量化它减少了多少跳变。

**修复机制。** 恢复时根据最新观测与最后输出建立偏移，然后重新接续运动，避免冻结距离一次性进入HID。压力恢复资格与位置接续分别判断；本次公开整理未改变这段算法。

**替代/失败。** 累计差值一次释放会给出错误跳跃；只靠更重平滑可能让微调更拖沓。维护者的“离线改善但实测没有改善”反馈改变了验证方法：快划和微调分开采集，各30秒，保留抬手/双指检查，而不是以单一平均指标判成功。

**验证。** 本轮确认整体回放输出、R1尾迹反例、入口/脱敏等价与完整固件编译。历史另有R2刷写读回匹配和BLE运行检查；已有32秒采样协议记录是此前同协议源验证的复用，不是R2新实物手感数据。

**状态。** 机制实现存在且参与当前回放；本轮未执行独立位置恢复消融或实机交互。R2刷后体验终验仍未取得，不能把历史刷写成功升级为已解决全部跳动。

## 贡献与证据如何归属

维护者直接提出场景与约束，并提供实物反馈、否决不达标体验、调整采样条件；部分技术诊断来自本人采纳的跨AI建议，AI执行具体C代码、工具、反例和构建。厂商提供芯片/评估设置，既有Zephyr/Nordic等提供运行基础；外部硬件合作成果不在这里宣称独立原创。

本次新工作是精选导出、来源/许可筛选、可移植回放入口、样本脱敏与等价性核验、可读文档；没有伪造早期提交、改写研发时间线或重写核心算法。
